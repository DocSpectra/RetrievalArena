# Stateless model-turn contract (ICSC development consumer)

`retrieval_arena/model_turn.py` owns a portable, one-turn boundary. Input is an ordered visible `system`/`user`/`assistant` history, currently allowed action names, provider/model/endpoint identity, maximum output tokens and provider-specific generation settings. The result is exactly one validated action and metadata with request/response SHA-256, raw response reference, call ID, finish status, reported usage fields (nullable), and latency. The caller owns corpus access, budgets, citation observation, scoring, pricing and outbound approval. The transport is injected, so this module has no network permission of its own.

`request_payload` builds the same stateless request body used by `ResponseTurn.complete` and by a caller's preflight token count. This keeps tool schemas, input messages and generation identity aligned; the caller decides which supported fields to submit to a provider's count endpoint. Token counting and spend admission remain caller responsibilities.

All functions request strict schemas and reject unknown keys locally. OpenAI calls request `tool_choice: required`, `parallel_tool_calls: false`, `store: false`, Standard/default service tier and medium reasoning. Ollama `/v1/responses` documents neither forced choice nor parallel control; these are omitted and local validation rejects zero/multiple/malformed calls. This limitation is recorded in each successful turn's `provider_schema_enforcement_verified: false`. Ollama is stateless; the consumer sends full visible history. The documentation consumer owns `evidence_ledger_v1` history compaction: it pins the task, records each action and `call_id` beside its result, deduplicates exact observed source lines, and preserves current permissions, notes and citation ranges in a single visible snapshot. Native Ollama and both Responses adapters consume the same snapshot content; limits may differ by backend. The full uncompressed trace and raw response references remain separate. The contract never relies on `previous_response_id`.

The first consumer is `../context/scripts/complex_task_agent_loop.py` through `../context/scripts/agent_model_provider.py` in the ICSC workspace. The local bridge permits only loopback `/api/tags` and `/v1/responses`, checks Qwen digest before and after a turn, and writes credential-free raw responses to ignored `artifacts/`. The OpenAI bridge requires `OPENAI_API_KEY`, exact SDK `openai==3.20.0`, no SDK retries, explicit outbound review for corpus data, and a pre-call cost reservation. The pinned SDK was installed in the ignored ICSC `.tools/` directory for a synthetic call and two separately approved four-cell corpus canaries. The second canary used `evidence_ledger_v1`: transport and trace replay succeeded, but one of four episodes produced an answer and three new trajectories reached the 45 KB history limit. This caller is not yet qualified for a larger Luna panel.

The ICSC September 30 development caller additionally uses exact OpenAI input-token preflight and trace-backed `working_evidence_v1` when the spend-derived token ceiling is reached. A separately frozen v5 canary completed four cited answers after two preserved output-cap partial attempts; independent answer judgments and live note use remain unverified. The new caller policy does not change the stateless RA turn contract or qualify candidate-provider images. See the ICSC `git/context/handoffs/2026-09-30-token-budget-canary.md` for the run record.

This package boundary does **not** alter candidate provider images, the Ragas judge image, network allowlists, receipt verification, or their existing native `/api/chat` contracts. Migrating any of them requires a separate image/network/receipt decision and validation. No candidate provider may gain external API access by importing this module.

Tests: `python -m unittest unit_tests.test_model_turn` from the RA root. Synthetic local execution and replay commands are recorded in the ICSC Sprint 07 handoff. The local synthetic Qwen response path demonstrated three one-function turns after a first attempt with an unaccepted plain-text second turn. This is an interface check, not answer-quality evidence.
