# Curated embedded-link ingress and diagnostic

`embedded_curated.v1` adds offline `curated-prepare`, `curated-select` and
`curated-verify` stages
to the immutable `refine-embedded-v2` operator. Consumers supply fixed pair/page
identities, full immutable development sources, per-pair dispositions and curator
assessments. No corpus names, provider transports, credentials or dependencies
are added. Existing model and fixture paths retain their meanings.

Preparation verifies every listed pair's source/group/hash binding and complete
audit coverage. It uses the exact source/anchor resolver and individual v2 editor;
keeps all rejected/omitted attempts; retains at most sixteen host-valid pairs by
canonical path rank interleaved over the frozen group order. It produces full-page
review evidence with role-bound IDs, exact UTF-8 bytes, explicit empty omission
lists and whole-pair byte ceilings. Both reviewers can receive identical packets
without curator scores/rationale, historical verdicts, groups, arms or numerics.
Consumer-owned checklists explain actual procedure coverage; the library does
not infer their scientific adequacy. No external review executes in this module.

`curator` is an explicit closed provenance branch in the existing v2 ledger.
Proposals and curator assessments use `curator` authority, never provider/model
identities or fabricated responses. Assessment dimensions, sum and manifest hash
are checked on replay. These AI-authored hypotheses are distinct from authored
fixtures and independently obtained AI references. The private legacy validation
projection remains internal and is never published as scientific provenance.

Analysis A scores every retained candidate, then selects k=1 within the highest
curator tier of each group. B defaults to explicitly unrun; the pool helper accepts
only caller-validated independent verdicts with both existing semantic gates and
first-review ranking. The helper is not a live B runner or review provenance
validator. A cannot establish independent defensibility. A later reviewed B after
observing A requires disclosure of that exposure and separate authorized execution.

Selection requires a consumer commit/hash receipt, verifies all frozen input
bindings, uses unchanged v2 q=.25/seeds/solver/denominator and scores all top-tier
then lower-tier alternatives within the existing group watchdog/cache ceiling.
Singleton costs are measured even though no competitive selection follows. All
primary groups seal before q=.10 diagnostics. Failures remain in their tiers;
ties/overlap/unavailable alternatives retain semantic fallback. Z must equal S.
Copies use exact v2 editor/set checks, unchanged prose/navigation, graph deltas,
idempotent assignment replay and externally anchored curator ledger tips. Cards
explicitly label curator-only diagnostic edits and include complete destination
source previews. No reader-benefit recommendation follows.

The separate verification stage checks all copied files and anchored ledgers,
recomputes every persisted primary/diagnostic start's energy and full gradient,
checks selected stationary starts, and freshly reruns all alternatives for every
claimed changed primary group with the same frozen seeds and settings.

Focused tests cover full-page bindings/blinding, A/B gates, closed provenance and
authority, reciprocal alternatives/set conflict, stale/incomplete audit refusal,
complete distinguishing/tie copy paths, replay and frozen-input tampering.
Existing numerical fixtures test actual distinguishing costs and true ties.
Portable Python uses the existing container limits; only Linux amd64 is exercised,
so RA-D09/D10 remain unresolved. No new deployment assumption or dependency.
